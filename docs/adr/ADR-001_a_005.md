# ADR-001: Español como lengua única

**Estado:** Aceptado (2026-08-11)
**Contexto:** El curso se imparte en español. Los estudiantes son hispanohablantes.
**Decisión:** Todo texto visible del juego y toda documentación está en español.
No hay ficheros `.en.md`, no hay parejas que sincronizar, no hay catálogo en inglés
obligatorio para cadenas ya españolas.

**Consecuencias:**
- La localización al inglés es opcional vía `locale/en.json`.
- Los tests `test_el_catalogo_esta_en_espanol.py` y `check_translations.py --ci`
  vigilan que el texto visible no mezcle idiomas.
- La política bilingüe previa fue sustituida expresamente por decisión del dueño.

# ADR-002: Separación hexagonal engine/framework

**Estado:** Aceptado (desde el inicio del proyecto)

**Contexto:** El motor (`src/engine/`) es material docente reutilizable; las
entidades y escenarios (`src/framework/`) son la capa de juego específica.

**Decisión:** `engine/core`, `ui`, `input`, `audio` y `utils` NO importan
`src.framework`. La única excepción documentada es `app.py`, que es el compositor
raíz y cablea ambos subsistemas.

**Verificación:** `lint-imports` (4 contracts kept) y
`tests/test_arquitectura_fronteras.py`.

# ADR-003: ECS bajo la jerarquía de entidades

**Estado:** Aceptado

**Contexto:** Se evaluó migrar todas las entidades a ECS puro vs mantener la
herencia BaseEntity → EnemyBase → EnemyWalker como capa principal.

**Decisión:** El ECS vive DEBAJO de la jerarquía de entidades, no en su lugar.
`BridgeComponentes` conecta ambos mundos. Las entidades de estudiantes usan la
herencia tradicional; los sistemas complejos (viento, láseres, sigilo) usan ECS.

**Consecuencias:** Los estudiantes no necesitan aprender ECS para entregar su
escenario; el motor usa ECS internamente para sistemas que lo justifican.

# ADR-004: Catálogo JSON propio vs gettext

**Estado:** Aceptado

**Contexto:** gettext requiere herramientas GNU externas y ficheros .mo binarios.

**Decisión:** Diccionario JSON por idioma + función `_()`. La clave es el literal
del código, no un identificador abstracto.

**Consecuencias:** Legible sin herramientas, editable en cualquier sitio,
revisable en pull requests. AUD-618 migró a claves canónicas (`ui.*`) para
permitir round-trip fiable entre idiomas.

# ADR-005: Física por contexto sin pymunk

**Estado:** Aceptado

**Contexto:** Se evaluó pymunk para colisiones y materiales de superficie.

**Decisión:** AABB propio con `PhysicsProfile` por modo de juego y capas de
colisión sobre el AABB (AUD-395). Sin dependencias físicas externas.

**Consecuencias:** Control total del comportamiento, cero dependencias C,
suficiente para un plataformas 2D educativo. Materiales de superficie viajan
en el perfil (GAP-039).
